# Minecraft 26.3 Port

## Sources

- Fork baseline: `e96ca7e55033e77f34da0d9d53eabac0b64aeb87` (26.2).
- Upstream master: [47fbb2fa](https://github.com/MeteorDevelopment/meteor-client/commit/47fbb2fa3ce3b76eb368ed944fb9e019115b40e1).
- Upstream 26.3 port: [mc-update](https://github.com/MeteorDevelopment/meteor-client/tree/mc-update), incorporated through [7a0c4032](https://github.com/MeteorDevelopment/meteor-client/commit/7a0c4032dcdac91af3968ff8c96de5fb096eba3d). This includes all five port commits: the snapshot and pre-release API updates, rendering fixes, and final mesh-upload/index-offset correction. Existing upstream authorship and licensing apply.

This update moves the fork's `master` branch to Minecraft 26.3. The previous 26.2 implementation remains in Git history. No published history is rewritten.

## Build

Use Java 25 and `./gradlew build`. The runtime jar is `build/libs/meteor-evfork-26.3-local.jar`. A clean task is not needed.

CI uses its run number instead of `local`, retains a per-commit artifact for 90 days, and updates the `latest` release only for `master`. Its asset remains `meteor-evfork-latest.jar`, with a SHA-256 checksum. Publishing this update replaces the rolling 26.2 download with the 26.3 build.

## Compatibility

- Fabric Loader 0.19.5+, Java 25, Minecraft 26.3.
- Compiled against Fabric API 0.161.0+26.3, Sodium 0.9.2, Lithium 0.26.2, and ViaFabricPlus API 5.1.1.
- Baritone uses the official upstream 1.20.0 API jar as a compile-only dependency. It is not bundled. The named `ComeCommand`/Freecam mixin is optional because upstream API jars obfuscate that implementation class; ordinary pathfinding uses the public API.
- Wurst is not bundled and neither mod declares a dependency conflict with the other. Overlapping movement, rendering, packet, and GUI modules can still interfere when enabled together. Shared keybinds also need manual review; this port does not migrate or alter settings.

Offline bytecode checks run during `check` without initializing Minecraft. They check declared mixin targets, shadow members, injection method selectors, and retained fork hooks. These checks do not prove injection ordinals, local captures, rendering output, or combined Meteor/Wurst runtime behavior. In-game verification remains required before treating the port as stable.
